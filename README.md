# Gen — 2027 S/S “Still Identity” ランディングページ

素の HTML / CSS / JavaScript のみで作られた 1 ページ構成の LP です。
ビルドツール（npm・webpack 等）は一切不要で、ファイルをそのままサーバーに置けば動きます。

---

## 1. 動かし方

`index.html` をダブルクリックしても表示できますが、**ローカルサーバー経由での確認を推奨**します。

```bash
# このフォルダの中で実行（Python が入っていれば追加インストール不要）
python3 -m http.server 8000
# → ブラウザで http://localhost:8000 を開く
```

> **なぜサーバー経由が良いか**
> `file://` で直接開くと、ブラウザのセキュリティ制限で一部の挙動（外部フォームの埋め込みなど）が
> 本番と変わることがあります。本番と同じ `http://` で確認するのが確実です。
> VS Code をお使いなら拡張機能「Live Server」でも同じことができます。

### クラス名の付け方（早見表）

| 接頭辞 | レイヤー | 役割 | 例 |
|---|---|---|---|

| `p-` | Project | このページ固有の塊 | `p-hero` `p-collection` |

## 4. 画像を差し替えるときの手順

1. `assets/img/` の同名ファイルに上書きする（HTML を触らずに済みます）
2. `index.html` の `width` / `height` 属性を、**新しい画像の実寸に合わせて更新する**
3. 形式は **WebP** を推奨（JPEG より 2〜3 割軽くなります）

> **なぜ `width` / `height` を書くのか**
> 画像の読み込み前にブラウザが表示場所を確保でき、読み込み後に他の要素が
> ガクッと動く現象（CLS）を防げます。**実寸と違う値を書くと効果がなくなる**ため、
> 差し替えのたびに必ず合わせてください。
> 枠の比率は CSS の `aspect-ratio` で固定しているので、多少縦横比が違っても
> レイアウトは崩れません（画像側が `object-fit: cover` でトリミングされます）。

> **⚠ 明るい写真に差し替えるときの注意**
> 現在の仮素材はすべて黒基調（暗い下地に光が浮かぶ絵）で、
> その明るさを前提に文字の減光量を決めています。
> 明るい写真に差し替えると、画像の上に載る文字が読めなくなる箇所が出ます。
> 差し替え後は次の 3 か所を見直してください（各CSSに必要な数値をコメントで書いてあります）。
> - ムービーの覆い … `project/collection.css` の `.p-movie__play`（明るい素材なら `0.40` → `0.68`）
> - MEMBER の覆い … `project/collection.css` の `.p-member__scrim`
> - フッターの覆い … `layout/footer.css` の `.l-footer::before`

## 5. 黒基調の設計（セクションの区切り方）

ページ全体が黒基調です。セクションの切り替えは**色を塗り分けず、グラデーションだけ**で表しています。

### 面の階調（`foundation/variables.css`）

| 変数 | 値 | 用途 |
|---|---|---|
| `--surface-0` | `#08090a` | 最も深い面。ページの地色、セクションの上下端 |
| `--surface-1` | `#0d0f0d` | わずかに持ち上げた面。セクションの中央付近 |
| `--surface-2` | `#12140f` | さらに持ち上げた面。入力欄・埋め込み枠など「触れる場所」 |

明度差はわずか 4〜6 しかありません。**これ以上開くと「黒い帯が並んでいる」ように見えてしまう**ためです。

### 区切りの作り方（`layout/main.css` の `.l-section::before`）

1 枚の疑似要素に 3 層のグラデーションを重ねています。

1. `--glow-moss`（深緑）の発光 … セクションごとに位置が変わる
2. `--glow-sand`（砂色）の発光 … moss とずらして置き、単色に見せない
3. 縦方向の階調 … 中央が `--surface-1`、上下端が `--surface-0`

発光の位置だけは各セクションの CSS が `--glow-x` / `--glow-y` で渡しています。
**光の当たり方を変えたいときは、その 4 行の % を書き換えるだけ**です。

```css
/* 例：object/project/about.css */
.p-about {
  --glow-x: 24%;   /* moss の発光の横位置 */
  --glow-y: 26%;   /* 同・縦位置 */
  --glow-x2: 82%;  /* sand の発光の横位置 */
  --glow-y2: 70%;  /* 同・縦位置 */
}
```

さらにセクションの境目には、両端が消える 1px の光の線を引いています（ベタの罫線にすると
線を「引いた」ことが目立ちすぎるため）。

### 1 セクションだけ白抜きにしたくなったら

明暗を切り替える仕組み（`data-tone`）は残してあります。
そのセクションの `data-tone="dark"` を `"light"` に変えるだけで、
**文字色・罫線・差し色・マウスストーカーの墨の色がまとめて反転**します。

## 6. アニメーション一覧と、止め方

11 種類入っています。**止めたくなったら `assets/js/motion-config.js` の該当行を `false` にするだけ**で、
HTML も CSS も触る必要はありません。

| 設定名 | 内容 | 定義場所 |
|---|---|---|
| `loader` | 導入演出：墨が一滴落ちて**ロゴ画像**が浮かぶ（初回訪問のみ） | `loader.css` / `loader.js` |
| `breathe` | 墨の呼吸：Hero とフッターの墨が 26〜34 秒周期で膨らむ | `motion.css` |
| `drift` | 霞の漂い：セクションの発光が 60〜74 秒周期で流れる | `motion.css` |
| `glowPulse` | **光のゆらぎ：背景の緑が 19〜23 秒周期でぼんやり明るくなっては沈む** | `motion.css` |
| `grainReact` | 粒子の反応：スクロールが速いほどグレインが立つ（0.05→0.13） | `motion.js` |
| `blurReveal` | にじみ出し：要素が「ぼけ→定着」で現れる | `reveal.css` |
| `splitHeading` | 見出しの一文字ずつ（40ms ずつ） | `motion.css` / `motion.js` |
| `parallax` | ルック画像が枠内で上下に動く（8% 前後） | `figure.css` / `motion.js` |
| `counterTick` | カウントダウンの**変わった桁だけ**が落ちてくる | `motion.css` / `countdown.js` |
| `cursorLabel` | 試料ラベル：カーソルの後ろに座標が薄く付いてくる | `cursorLabel.css` / `cursor-label.js` |
| `typewriter` | 研究記録の本文を1文字ずつ打ち出す | `typewriter.css` / `typewriter.js` |

```javascript
// assets/js/motion-config.js
window.GEN_MOTION = {
  loader: true,
  breathe: true,
  drift: false,   // ← 例：霞の漂いだけ止める
  …
};
```

### 演出を作るときに守っているルール

- **常時動くものは `transform` と `opacity` だけで作る**
  この 2 つは合成（composite）だけで処理され、レイアウト計算や再描画が起きません。
  `background-position` や `top/left` を毎フレーム変えると、スクロール中にカクつきます。
- **JS は「材料」を渡し、組み立てはCSSに任せる**
  例：パララックスは JS が `--parallax-y` を渡すだけで、
  `transform` の組み立ては `figure.css` が行います。JS がインラインで `transform` を
  書いてしまうと、CSS 側のホバー拡大が必ず負けて効かなくなります。
- **止まったら計算も止める**
  スクロールが止まって約 0.5 秒で `requestAnimationFrame` のループを抜けます
  （ノートPCのバッテリー対策）。次のスクロールで自動的に再開します。
- **`prefers-reduced-motion: reduce` なら全部止める**
  そのときもページの内容は最初からすべて表示されます（読めなくなる演出は作らない）。

## 7. 数値の組版ルールと標本ラベル

### 数値のルール（`component/numeric.css`）

数字の書式が揃っているかどうかで、精度の印象はほぼ決まります。このサイトでは次の 6 つを守っています。

| # | ルール | 例 |
|---|---|---|
| 1 | 数字は必ず等幅（`tabular-nums`）。桁が縦に揃い、更新時も幅が動かない | カウントダウン・日付・価格すべて |
| 2 | 桁区切りはカンマ（4桁以上） | `¥6,000` |
| 3 | 日付はゼロ埋めの 4-2-2。3月を `3` と書かない | `2027.03.20` |
| 4 | 単位は数値より小さく・薄く、アキを空けて添える | `180 席` `128 g/m²` |
| 5 | 区切りは全角「／」ではなく半角スラッシュ＋アキ | `17:30 / 18:00` |
| 6 | 機械可読な値は `datetime` 属性で別に持つ | `<time datetime="2027-03-27">2027.03.27</time>` |

使い方：`.c-num`（等幅数字）、`.c-num__unit`（単位）、`.c-num__currency`（通貨記号）の 3 クラスだけです。
数値だけで構成される箇所（カウンター・日付リスト・開催情報）は、各コンポーネントのCSSに直接
`font-variant-numeric` を書いてあるので、HTML 側でクラスを付ける必要はありません。

### 標本ラベル（`.c-spec`）

各ルックに、生地と染色の仕様表を添えています。

```
WARP ·········· 60/1 Linen
WEFT ·········· 40/1 Linen
GSM  ·········· 128 g/m²
LOT  ·········· 2703-A
```

**架空の記号ではなく、実際の生産現場にその服が必ず持っている値**を使っているのが要点です。
番手・目付（GSM）・染色ロットは、撮影素材に差し替えたあともそのまま使い続けられます。
値を書き換えるのは `index.html` の `<dl class="c-spec">` 内だけです。

> **点線について**：項目名と値をつなぐ点線は `dt` の疑似要素で描いています。
> `dl` の直下に置けるのは `dt` / `dd`（とそれを包む `div`）だけなので、
> 線を引くために `span` を挟むと HTML として不正になるためです。

### コンセプト本文の打ち出し（`.c-type`）

About のコンセプト本文は 1 文字ずつ打ち出されます。長文なので、次の 4 点を守っています。

- **レイアウトが 1px も動かない**
  同じ文章を 2 枚重ねています。1 枚目（`.c-type__ghost`）は文字色だけ透明にした全文で、
  最初から最終的な高さを確保する「場所取り」。2 枚目（`.c-type__out`）をその上に重ねて打ち出します。
  空の要素に文字を足していく作り方だと、文章が伸びるたびに下の要素が押し下げられ続けます
- **全文は最初から HTML にある**
  読み上げ・ページ内検索・コピーは、打ち出しの進み具合に関係なく常に全文が対象です。
  **JS が動かない環境では、普通の文章としてそのまま表示されます**
- **読み手を待たせない**
  1 行ずつ順番に打ちますが、順番が回ってきた時点でその行が画面の上へ流れていたら、
  打たずに即表示します。また**どこかをクリックすれば全文が即座に出ます**
- **速度は `data-type-speed` で変えられる**
  `index.html` の `<div class="p-about__concept" data-type-speed="18">` の数字が
  1 文字あたりのミリ秒です。大きくすると遅くなります（既定 18ms ＝ 読む速度の約 10 倍速）

> **文言の直し方**：`index.html` の `<p class="c-type__line">…</p>` を書き換えるだけです。
> 段落を増やす／減らすときも、この `<p>` を足し引きするだけで動きます（JS は触りません）。

## 8. いま一時的に隠している箇所と、戻し方

公開前の段階として、次の4か所を**消さずに隠して**います。
マークアップは一切削っていないので、`hidden` 属性を外す／コメントを外すだけで元に戻ります。

| 隠しているもの | 戻し方 |
|---|---|
| **About セクション**（コンセプト本文） | `index.html` の `<section id="about" … hidden>` から `hidden` を消す。本文は研究記録に分割済みなので、戻すと内容が重複します |
| **Collection セクション** | `index.html` の `<section id="collection" … hidden>` から `hidden` を消す |
| **Journal セクション** | `index.html` の `<section id="journal" … hidden>` から `hidden` を消す |
| **ヘッダー／フッターのナビ 2項目** | `index.html` 内の「【一時非表示】」コメント 4か所を外す（各2行） |
| **Exhibition の会場・チケット・予約フォーム・注意事項** | `p-exhibition__coming` のブロックを削除し、続く4ブロックの `hidden` を消す |
| **「:: Designer」などの大見出し（`.c-sectionTitle`）** | 下の「大見出しを戻すとき」を参照（2手順） |
| **Exhibition の開催日** | `<p class="p-exhibition__date" … hidden>` から `hidden` を消す |
| **お問い合わせフォーム** | `<form class="c-form p-contact__form u-hidden">` から `u-hidden` を消し、下の `p-contact__mail--solo` から `--solo` を外す（2か所セット） |

**大見出しを戻すとき**

いまセクションの題名を担っているのは、小さなラベル（`SEC.02 — Exhibition`）のほうです。
大見出しを戻す場合は、題名の役割も一緒に戻す必要があります。

1. `index.html` の `<h2 class="c-sectionTitle" … hidden>` 6か所から `hidden` を消す
2. 同じセクションのラベル `<p class="c-label js-sectionLabel" …>` から
   `role="heading" aria-level="2"` を消し、`<section>` の `aria-labelledby` を
   `"xxx-label"` から `"xxx-title"` に戻す

> **2 を忘れるとどうなるか**
> 見出しが h2 二つ（大見出しとラベル）になり、読み上げの見出し一覧に
> 同じセクションが二重に並びます。見た目は何も変わらないため気づきにくい箇所です。
> 逆に 2 だけ戻して 1 を忘れると、そのセクションには見出しが1つも無い状態になります。

**あわせて戻すもの**

1. **セクション番号**：いまは詰めて `SEC.01 About / SEC.02 Exhibition / SEC.03 Contact`。
   本来は `01 About / 02 Collection / 03 Exhibition / 04 Journal / 05 Contact` です
   （該当箇所に「【一時変更】本来は SEC.0x」とコメントを入れてあります）
2. **Hero の「and more」のリンク先**：いま `#exhibition`。Journal 公開時に `#journal` へ戻す
3. **構造化データ（head の JSON-LD）**：会場 `location` とチケット `offers` を外しています。
   事実と違う会場名を検索結果に出さないためです。決まり次第、JSON-LD のコメントに
   書いてある形で戻してください（Google のイベント表示は `location` が必須のため、
   戻すまでは検索結果のイベント詳細表示の対象外になります）

> **なぜ `hidden` 属性なのか**
> HTML を削ると、戻すときに「どこに何があったか」を探すことになります。
> `hidden` が付いた要素は画面にも読み上げにも出ず、中の画像（`loading="lazy"`）も
> 読み込まれないため、**消したのと同じ効果**が得られます。
> なお `foundation/reset.css` に `[hidden] { display: none !important; }` を入れてあります。
> 後から `display: grid` などを指定した要素に `hidden` を付けても、必ず隠れるようにするためです。

## 9. お問い合わせフォームの送信先メールアドレス

**先に結論**：HTML だけではメールは送れません。「フォームの内容を受け取ってメールに転送するサービス」を
1つ挟むのが、サーバーを用意しない場合の標準的なやり方です。
受信するメールアドレスは**そのサービスの管理画面に登録**します（HTML には書きません）。

### 方法A：フォームサービスを使う（推奨・サーバー不要）

Formspree / formrun / SSGform など。無料枠で始められます。ここでは Formspree を例にします。

1. サービスに登録し、**受信したいメールアドレス**（主催側のアドレス）を登録する
2. フォームを1つ作ると、`https://formspree.io/f/xxxxxxx` のような**送信先URL**が発行される
3. `index.html` のフォームタグに、その URL と送信方法を追記する

```html
<!-- 変更前 -->
<form class="c-form p-contact__form" id="js-contactForm" novalidate>

<!-- 変更後（action と method を足すだけ） -->
<form class="c-form p-contact__form" id="js-contactForm" novalidate
      action="https://formspree.io/f/xxxxxxx" method="post">
```

4. `assets/js/form.js` の送信処理を、ふりではなく実際の送信に差し替える

```javascript
// assets/js/form.js の sendForm（「送信処理の差し替えポイント」とコメントがある関数）
// form 変数は同じファイルの上で取得済みなので、引数は不要です。
function sendForm() {
  return fetch(form.action, {
    method: 'POST',
    body: new FormData(form),
    headers: { 'Accept': 'application/json' }   // ← Formspree にJSONで返させる指定
  }).then(function (res) {
    if (!res.ok) throw new Error('送信に失敗しました');
  });
}
```

> **なぜ HTML にメールアドレスを書かないのか**
> ① 静的な HTML にアドレスを書いても、そこへメールは飛びません（送る仕組みが無い）
> ② ソースに平文で書かれたアドレスは、迷惑メール業者の収集プログラムに拾われます
> サービス側に登録しておけば、**アドレスを変えるときもサービスの管理画面だけで完結**します。

### 方法B：レンタルサーバーの PHP を使う

さくら・エックスサーバー等、PHP が動くサーバーに置く場合は、`contact.php` のような
送信スクリプトを1つ置き、**その PHP の中にアドレスを書きます**（HTML には書きません）。

```php
<?php
$to = 'info@example.com';   // ← ここに主催側のアドレス
```

この場合、HTML 側は `action="contact.php" method="post"` に変えるだけです。
ただし **迷惑メール対策・文字コード・送信元ドメインの設定（SPF など）を自分で面倒みる必要**があり、
設定を誤ると「送信は成功しているのに迷惑メール扱いで届かない」が起きます。
初めての場合は方法Aを強くおすすめします。

### 方法C：Google フォームにそろえる

チケット予約で Google フォームを使う予定なので、**お問い合わせも Google フォームに寄せる**という
選択肢もあります。回答は Google フォームの所有者アカウントに届き、
設定で「新しい回答のメール通知」を有効にすれば、登録したアドレスへ通知が飛びます。
管理画面が1つで済むのが利点ですが、現在のフォームの見た目はそのままでは使えません
（Exhibition と同じ埋め込み枠に置き換えることになります）。

### どの方法でも必ず守ること

- **入力チェックはサーバー側でも行う**
  いまブラウザ側で動いているチェックは、開発者ツールから迂回できます。
  フォームサービスを使う場合は、サービス側のスパムフィルタ（reCAPTCHA 等）を有効にしてください
- **「送信できなかったとき」の導線を残す**
  現在すでに、フォームの下に `contact@example.com` へのメールリンクを置いてあります。
  ここは実際のアドレスに差し替えてください（**こちらは公開前提のアドレス**なので、
  収集対策として別途フリーアドレスを使うか、問い合わせ専用アドレスを推奨します）
- **送信後の表示**
  現在は画面内にメッセージが出るだけでページ遷移しません。
  サービスによっては「送信完了ページへ飛ばす」設定が既定になっているので、
  その場合は `fetch` を使う上の形にすると、ページ遷移せずに現在の表示のまま完了できます

## 13. 研究記録（RESEARCH RECORD）

架空の研究所が公開している「研究記録の断片」として、4か所に分けて配置しています。

| 位置 | 内容 | STATUS | 見た目の状態 |
|---|---|---|---|
| デザイナー紹介の**前** | RECORD 01 | `STABLE` | 実線の罫線／基準位置／属性がすべて埋まっている |
| デザイナー紹介の**後** | RECORD 02 | `UNSTABLE` | 破線の罫線／わずかに右へずれる／行間が少し広い |
| 開催日時の**後** | RECORD 03 | `OBSERVING` | 罫線が右端で消える／左へ戻る／試料番号が欠落 |
| Contact の後・footer の前 | エンドコメント | （なし） | 見出しを持たない。中央に置いた1本の線だけで場面を変える |

### 「研究が進むほど記録が不安定になる」の作り方

文章で説明せず、**罫線・位置・情報量の3点だけ**で示しています。奇抜に崩すと資料としての
説得力が落ちるため、変化幅はどれも小さく取ってあります（横位置のずれは 1024px 以上でのみ有効。
狭い画面ではただ読みにくくなるだけなので止めています）。

STATUS の点も**色では区別していません**。赤・黄・緑はパレットから浮くうえ、色だけで意味を
伝えると色覚特性のある方に届かないためです。**点滅の仕方**で3つの状態を書き分け、意味そのものは
必ず文字（`STATUS : STABLE` など）でも示しています。

- `STABLE` … 点灯したまま動かない
- `UNSTABLE` … ゆっくり明滅する
- `OBSERVING` … 一定間隔で短く光る

RECORD 03 の属性欄は `SPEC. ███ / OBS. 2027.03.20 — / REC. OPEN` です。
観測日が開催日のまま閉じていない（`—`）ことと、記録が `OPEN` のままであることで、
**まだ書き込まれている最中**であることを示しています。
伏せ字は読み上げでは「（記録欠落）」として読まれます。

### タイピングの仕様

`assets/js/typewriter.js` が、HTML に書かれた文章を1文字ずつ DOM に追加していきます
（CSS の `width: 0 → 100%` で見せる方式ではありません）。

- **打鍵間隔にゆらぎがある**：基本の間隔に ±35%。これが無いと、どれだけ間を足しても機械的に見えます
- **句読点で止まる**：`。！？` のあとは打鍵7文字分、`、` のあとは3.5文字分の間が空きます。文を言い切ったあとの沈黙です
- **ときどき考え込む**：60回に1回ほど、110〜330ms 手が止まります
- **行が変わるときに間が空く**：改行のあとは打鍵6文字分
- **画面の更新間隔に速度を食われない**：次の1文字の時刻を「現在時刻＋間隔」ではなく
  「前回の予定時刻＋間隔」で進めています。現在時刻を基準にすると、20ms の予定でも
  画面の更新（約16.7msごと）を待って33msかかり、指定より常に遅くなります
- **打ち終わってもカーソルが残る**（`data-type-caret="keep"`）：完成した印刷物ではなく、作業中の画面に見せるため
- **ユーザーがそこへ辿り着いてから打ち始める**（Intersection Observer）
  判定の範囲を画面の上から60%までに絞っているので、**画面の下端にちらっと見えた段階では始まりません**。
  その記録が画面の真ん中あたりまで上がってきて、読もうと目を留めた位置で打ち始まります
  （下端に顔を出した瞬間に始めると、辿り着いたときには打ち終わっていて演出が見られません）。
  ページ最下部まで来ても始まっていない塊があれば、そこで必ず開始する保険も入れてあります
- **リロードすると最初から**：状態を保存していないので、毎回打ち直されます

速度は HTML の `data-type-speed`（1文字あたりのミリ秒）で変えられます。
記録は `26`、エンドコメントは `28`（最後だけ少しゆっくり）。
句読点などの「間」はすべてこの値に対する倍率なので、**この数字を変えるとリズムを保ったまま
全体の速さだけが変わります**。RECORD 01（164文字）で打ち切りまで約8.5秒です。

### 文言を直すとき

`index.html` の `<p class="c-type__line">` の中身を書き換えるだけです。**改行位置がそのまま
表示の改行位置**になります（原稿の改行を活かすため、JS 側で改行を潰していません）。
JS は一切触る必要がありません。

### 読めなくなる状況を作らない

- **全文は最初から HTML にあります**。読み上げ・ページ内検索・コピーは、打ち出しの進み具合に
  関係なく常に全文が対象です
- **JS が動かない環境では、普通の文章としてそのまま表示されます**（確認済み）
- **「動きを減らす」設定では打ち出しをしません**。最初から全文が出ます
- **行間は 2.0**（RECORD 02 のみ 2.12、エンドコメント 2.1）。原稿の改行をそのまま1行として
  使うため通常の本文より広めですが、2.4 では行が離れすぎて「1つの記録」ではなく
  「並んだ短文」に見えてしまうため詰めました
- **どこかをクリックすれば全文が即座に出ます**。読む速度は人それぞれなので、逃げ道を用意しています

## 14. 書体（Webフォント）とロゴ画像

### 読み込んでいる書体

`index.html` の `<head>` で Google Fonts から 3 書体を読み込んでいます。

| 書体 | 使っている場所 | 変数 |
|---|---|---|
| **DotGothic16** | 研究記録の打ち出し・エンドコメント／Hero とフッターのカウントダウン | `--font-dot` |
| **New Tegomin** | 本文の基本書体（`body` と見出しの和文） | `--font-base` / `--font-serif` |
| **Noto Sans JP** | 11〜13px の小さい文字だけ | `--font-ui` |

欧文のラベル・ボタン（`SEC.01 — DESIGNER` など）は **変更していません**。
Arial（`--font-display`）と等幅（`--font-mono`）のままです。
ここまで和文書体に寄せると、研究機関らしい「計器の表示」という性格が薄れてしまうためです。

### なぜ小さい文字だけ Noto Sans JP なのか

**実測で判断しています。** 3 書体の実ファイルを取り寄せ、黒地（`#08090a`）に
11 / 13 / 16 / 19px で並べて比較しました。

- New Tegomin は**筆で書いたような細く不均一な線**を持つ書体です。16px 以上では
  その揺らぎが持ち味になりますが、**11〜13px・薄い文字色（`#a8ada7`）では線が消え、
  画数の多い漢字が潰れます**。
- コントラスト比は足りていても（AA は満たしています）、**字形そのものが判別できない**という
  別の問題なので、色を濃くしても解決しません。

そこで、**小さい文字だけ** `--font-ui`（Noto Sans JP）に逃がしました。該当箇所：

```
c-form__error / c-form__status / c-form__note      … フォームの注記・エラー
c-newsList / c-defList                              … 日付つきリスト・定義リスト
p-member__body                                      … MEMBER ブロックの本文
p-exhibition__venue / __ticketLead / __notes / __comingNote
u-skipLink                                          … スキップリンク
```

**全部 Noto Sans JP にしたい場合**は `foundation/variables.css` の `--font-base` と
`--font-serif` の先頭を `"Noto Sans JP"` に書き換えるだけです（1 か所ずつ、計 2 行）。

### DotGothic16 のサイズを `clamp()` で変えていない理由

DotGothic16 は **16px グリッドで設計されたドット書体**です。16 の倍数以外のサイズにすると
ドットが半端な位置に落ちて輪郭がぼやけ、「ドット書体である」という手触りが消えます。
そのため記録本文は `1rem`（16px）、カウントダウンは `1.5rem → 2rem` の**2 段階**に
切っており、画面幅に応じて連続的に変化させていません。

### フォント URL について

```
https://fonts.googleapis.com/css2?family=DotGothic16&family=New+Tegomin&family=Noto+Sans+JP:wght@437&display=swap
```

ご指定のURLをそのまま使っています。`Noto Sans JP` の `wght@437` は可変フォントの
太さ指定で、このままでも動きます（400 と 500 の中間の太さになります）。
**標準の太さにそろえたい場合は `437` を `400` に変えてください。**

> **表示速度への影響**
> Webフォントは和文で 1 書体あたり数百KB あり、追加すると初回表示が遅くなります。
> `display=swap` を付けているので「文字が見えない時間」は発生せず、
> 代替フォントで先に表示 → 読み込み後に切り替わります（切り替わる瞬間に字幅が動きます）。
> 気になる場合は 10 章の「サブセット化」を検討してください。

### ロゴ画像

| ファイル | 場所 | 表示サイズ |
|---|---|---|
| `assets/img/logoset_white.png`（321×511） | Hero の `<h1>` | 高さ `clamp(9rem, 5rem + 18vh, 22rem)` |
| `assets/img/symbol_white.png`（321×378） | ヘッダー左上 | 高さ `1.75rem` |

- **幅ではなく高さで大きさを決めています。** どちらも縦長のため、幅基準だと画面が広いときに
  縦へ伸びすぎてファーストビューから溢れます。
- Hero のロゴは `fetchpriority="high"` を付けて最優先で読み込ませています（LCP 対策）。
- 文字だった頃の `text-shadow` は画像では効かないため、**`drop-shadow`** に置き換えています
  （`box-shadow` だと透過PNGの四角い枠に影が付きます）。

  ここがずれると CLS 対策が効かなくなります（→ 4章）。

## 15. セクション題名の縦置き

### 何をしているか

大きな「:: Designer」の見出し（`.c-sectionTitle`）を `hidden` にし、代わりに
小さなラベル **`SEC.02 — Exhibition`** がセクションの題名を担っています。
1024px 以上では、このラベルを**時計回りに90度回してセクションの左端**に置き、
**そのセクションが画面の中央付近にあるあいだだけ**表示します。

| 画面幅 | 題名の置き方 |
|---|---|
| 〜1023px | 横組みのまま、セクション上部に中央寄せ（14px）。狭い画面には縦書きを置く余白が無いため |
| 1024px〜 | 左端に縦置き（16px）。入るときフェードイン、出るときぼけながらフェードアウト |

### 回し方：なぜ `writing-mode` ではなく `transform: rotate` なのか

`writing-mode: vertical-rl`（縦書き）にすると欧文は回りますが、`—` や `.` の向き、
字間の扱いが**縦組みの規則に切り替わって**しまいます。
ここで欲しいのは「横組みのまま、紙を回した」状態なので、組み方は変えずに箱ごと回しています。
結果、字間（`--ls-wide`）も末尾の罫線（`::after`）もそのまま一緒に回ります。

`rotate(90deg)`（時計回り）にすると、文字の「下」を指していたベクトルが「左」を向きます。
ご指定どおり**ベースライン側が画面の左端を向いた**状態です。

`transform-origin: left top` にしているのは位置を計算可能にするためです。
既定の中心（`50% 50%`）で回すと箱の幅ぶん位置が飛びますが、左上を軸にすると
回転後の箱は「基準点の左へ、下に向かって」伸びるだけなので、
`left` / `top` の値がそのまま見た目の位置になります。

### 出し入れの判定（`assets/js/section-label.js`）

- 監視しているのは**ラベルではなくセクション**です。ラベルは縦に数百pxしかないので、
  ラベルを監視すると「ラベルは画面外・セクションはまだ画面内」で消えてしまいます
- `rootMargin: '-25% 0px -25% 0px'` ＝ **画面の中央50%**にセクションが掛かったら表示。
  画面端にセクションが1行覗いただけで出ると、スクロール中に明滅して落ち着きません
- `reveal.js` と分けてあるのは、あちらが「1回出したら監視をやめる」演出なのに対し、
  こちらは**出入りを何度でも扱う**必要があり、ルールが正反対だからです

動かしているのは `opacity` と `filter: blur()` と `transform` だけです。
いずれも再レイアウトを起こさず合成だけで処理されるため、スクロール中でも負荷が出ません。

> **止めたいとき**：`object/component/heading.css` の
> `.c-sectionHead .c-label` から `opacity: 0` と `filter` の行を消すと、常時表示になります。
> 「動きを減らす」設定のときは自動で常時表示になります（確認済み）。

### 文字サイズを一段上げたことについて

黒地に細い書体（New Tegomin）という組み合わせでは、**白抜き文字は線が細って見える**ため、
同じ級数でも紙や白地より一回り小さく感じられます。
`foundation/variables.css` のスケールを全体に 1〜2px（8〜10%）持ち上げました。

| 変数 | 変更前 | 変更後 |
|---|---|---|
| `--fs-xs` | 11px | **12px** |
| `--fs-sm` | 13px | **14px** |
| `--fs-base` | 14→16px | **15→17px** |
| `--fs-md` | 16→18px | **17→19px** |
| `--fs-lg` | 20→28px | **21→30px** |
| `--fs-xl` | 28→48px | **30→52px** |

世界観を変えない範囲に留めるため、上げ幅は一段までにしています。
研究記録とカウントダウンの **DotGothic16 は 16px / 32px のまま**です
（ドットが整う寸法から外せないため。理由は 14 章）。
変更後に全幅（320 / 390 / 768 / 1024 / 1920px）で横はみ出しが無いこと、
表示中テキスト89か所すべてが AA を満たすことを再測定して確認済みです。

## 16. 背景の光のゆらぎ（glowPulse）

### 何をしているか

セクションの背景にある**緑（moss）の発光だけ**が、ぼんやり明るくなってはまた沈みます。
周期は偶数番目のセクションが 19 秒、奇数番目が 23 秒。
揃った周期にすると「ページ全体が点滅している」ように見えるため、わざとずらしています。

濃さの振れ幅は **0.40 〜 0.72**（基準 0.55 の上下 ±0.17）。
「気づくと明るさが変わっている」程度で、これ以上広げると点滅として知覚され、
「ゆったり」という狙いから外れます。

### なぜ `@property` が必要なのか

CSS変数は本来ただの文字列なので、`0.40 → 0.72` のような**中間の値が計算できません**。
そのままアニメーションさせると、値が途中でパッと切り替わって段階的に見えます。

```css
@property --glow-moss-a {
  syntax: "<number>";   /* ← 「これは数値だ」と型を宣言する */
  inherits: true;       /* ::before から参照するので継承させる */
  initial-value: 0.55;
}
```

こう宣言するとブラウザが中間の値を計算できるようになり、なめらかに変化します。
（同じ手法をルック画像の寄り＝`figure.css` の `--img-scale` でも使っています）

実測で `0.499 → 0.538 → 0.580 → 0.617 → 0.652 → 0.680 → 0.702 → 0.715 → 0.720` と
連続的に変化することを確認済みです。

### なぜ `filter: brightness()` で明滅させなかったのか

グラデーション全体を明るくすると、緑だけでなく**面の地色や砂色の光まで一緒に明るくなります**。
地色が持ち上がると、その上に載る文字とのコントラストが落ちて読みにくくなる方向に動きます。
濃さを持つ変数を1つだけ動かせば、変化するのは緑の層だけで済みます。

**最も明るい 0.72 の状態で表示中テキスト89か所すべてを再測定し、AA を満たすことを確認済み**です
（moss は `rgb(46 56 27)` という暗い色なので、濃くしても地は明るくなりません）。

### 止め方・調整の仕方

| やりたいこと | 触る場所 |
|---|---|
| 明滅だけ止める（漂いは残す） | `motion-config.js` の `glowPulse: false` |
| 明滅を速く／遅くする | `motion.css` の `animation-duration` の**2つ目**の値（19s / 23s） |
| 振れ幅を変える | `motion.css` の `@keyframes c-glowPulse` の 0.40 / 0.72 |
| 緑そのものの色を変える | `variables.css` の `--glow-moss-rgb` |
| 明滅なしの基準の濃さを変える | `variables.css` の `--glow-moss-a` |

> **`animation` の shorthand ではなく個別指定にしている理由**
> `.l-section::before` には漂いと明滅の2つが重なっています。
> 「奇数番目は逆回り」の指定が `animation-direction` / `animation-duration` を上書きするため、
> shorthand のままだと、その上書きが明滅のほうにも掛かってしまいます。
> 個別指定（`animation-name: c-driftX, c-glowPulse;`）なら、
> カンマ区切りで「1つ目＝漂い／2つ目＝明滅」と対応が取れます。

「動きを減らす」設定のときは、漂いとあわせて自動で停止します（確認済み）。

## 17. 開催日・フォーム・SNS まわりの現在の状態

### カウントダウンの起点日

**2027年3月27日（土）／ 時刻は未公開**です。

`data-deadline` は `2027-03-27T00:00:00+09:00`（その日の0時）を指しています。
時刻を公開していないため、`18:00` のような時刻を含む値は入れていません。
時刻が決まったら、次の4か所を同じ値に更新してください。

| # | 場所 | 現在の値 |
|---|---|---|
| 1 | Hero の `data-countdown` | `2027-03-27T00:00:00+09:00` |
| 2 | フッターの `data-countdown` | 同上 |
| 3 | Exhibition の `<time datetime>` | `2027-03-27`（現在 `hidden`） |
| 4 | head の JSON-LD `startDate` / `endDate` | `2027-03-27`（日付のみ） |

> **JSON-LD を日付だけにしている理由**
> schema.org は `YYYY-MM-DD` の日付のみの指定も正式に認めています。
> 未公開の時刻を仮で書くと、検索結果に事実と違う開始時刻が出てしまうため、
> **分かっている情報だけを書く**方針にしています。

> **過去の日付を入れたときの挙動**
> `countdown.js` は開催日を過ぎると `000:00:00` で固定します（NaN や負の数は出しません）。
> テストで過去の日付を入れると 0 のまま止まるのは正常な動作です。

### Exhibition：開催日も非公開に

開催日を `hidden` にし、**Coming soon** がセクションの主役になりました。
文字サイズは以前の 14px から `--fs-xl`（30→52px）へ引き上げています。
日付の添え物としての寸法のままでは、主役に据えるには小さすぎるためです。

字間は 0.32em のまま据え置きました。大きくしたうえに字間まで詰めると、
英字が1つの塊になって「掲示」ではなく「ロゴ」に見えてしまいます。
なお `letter-spacing` は最後の1文字のうしろにも入るため、
右側の `padding` を字間ぶん差し引いて、光学的に中央へ戻しています。

### Contact：フォームを一時非公開、メールアドレスを主役に

- リード文（取材・受注…）を**中央寄せ**に変更
- フォームは **`u-hidden`** で非表示。`display:none` なので、
  **隠れているあいだは Tab キーでも入力欄に入れません**（確認済み：フォーカス可能な入力 0個）
- メールアドレスは「または」を外し、`p-contact__mail--solo` で大きく単独表示

**戻すとき**は2か所セットです。`form` から `u-hidden` を外し、
`p-contact__mail` から `--solo` を外すと、以前の「フォーム＋または〜」の形に戻ります。

> **`hidden` 属性ではなく `.u-hidden` クラスにした理由**
> 効き方はどちらも `display:none` で同じですが、HTML を読んだときに
> **「仕様として非公開」なのか「運用上いったん止めている」のか**が区別できるよう、
> 意味の指定（`hidden` 属性）と見た目の指定（Utility クラス）を分けています。
> 定義は `object/utility/utility.css`。

### SNS：YouTube を削除、IG / X をロゴ画像に

| | 変更前 | 変更後 |
|---|---|---|
| Instagram | 文字「IG」 | `assets/img/sns_instagram.png` |
| X | 文字「X」 | `assets/img/sns_x.png` |
| YouTube | 文字「YT」 | **削除** |

丸い罫線・ホバー時の浮き上がり（-2px）・フォーカスリングは**すべてそのまま**です。

画像の濃さは **平常時 `opacity: 0.55` → ホバー／フォーカスで `1`**。

> **`filter` ではなく `opacity` を選んだ理由**
> `filter: brightness()` は「元の色を暗くする」処理なので、白い画像が灰色になるだけで、
> **背面の墨や発光が透けません**。そこだけ貼り付けた素材のように浮いて見えます。
> `opacity` なら背景が透けるため、周囲の濃淡の中に自然に沈みます。

薄さの下限は実測で決めています。描画結果のピクセルを測定したところ、
`0.55` のときのアイコンと背景のコントラストは **6.55:1**。
アイコンは WCAG 1.4.11（非テキストコントラスト **3:1**）の対象なので倍以上の余裕があります。
`0.3` まで下げると約 3.2:1 で基準ぎりぎりになるため、**0.55 を下限**としました。

`alt` は空にしています。リンクの名前は隣の `u-visuallyHidden` が持っているので、
画像にも `alt` を書くと「Instagram Instagram」と二重に読み上げられるためです。

### Hero のロゴとカウントダウン

- ロゴを**器（`l-container`）の右端に揃え**、高さの上限を 22rem → **30rem** に拡大
  - `img` は `display:block` なので親の `text-align: right` では動きません。
    ブロック要素を右へ寄せるのは **`margin-left: auto`** が定石です
  - **767px 以下では右寄せしていません。** 狭い画面ではニュースもカウンターも
    中央に寄せているため、ロゴだけ右に振ると軸が合わずに崩れて見えます
- カウントダウンを Hero・フッターとも **24/32px → 32/48px** に拡大
  （ドット書体なので 16 の倍数から選んでいます。理由は 14 章）
